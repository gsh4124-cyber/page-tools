## 인증부터 요구하던 첫 화면 개선

첫 화면을 이메일 폼에서 서비스 소개로 바꿨다. 글·사진·영상 다이어리의 용도, 스티커를 넣은 예시 기록, 기록/달력 예시 전환, 습관과 암호화 백업 설명을 먼저 제공한다. 실제 사용자 데이터나 외부 이미지/추적 코드를 사용하지 않는다. 현재 개인용 운영이며 기존 소유자 계정만 실제 앱에 접근한다는 점을 명시한다.

로그인 폼은 ‘내 모아 열기’를 누른 뒤 native dialog로 연다. 이메일 메일 발송은 자동 실행하지 않고 폼 제출 때만 수행한다. 받은 링크 입력은 메일 요청 성공 뒤 또는 ‘이미 로그인 메일을 받았어요’를 선택한 뒤 표시한다. 기존 인증/쿠키/RPC/RLS는 그대로다.

새 실제 호스트에서 소개 화면·로그인 폼 초기 비노출·예시 달력 전환·사용자 선택 후 로그인 창 표시를 확인했다. 현재 앱 내 브라우저의 clientWidth 304px, scrollWidth 304px로 가로 넘침이 없다. 좁은 패널에서 제목 크기와 회전 배경의 넘침을 보완했다. 브라우저 패키지 검사는 innerWidth 대신 clientWidth와 비교하도록 고쳤다. 이번 새 대화형 창에서 실제 메일 발송·소유자 재로그인·개인 기록 변경은 재실행하지 않았다. 기존 실제 소유자 인증 결과와 구분한다.

사용자 선택대로 **앱 전체와 파일은 소유자 전용**이다. 서비스 소개·명시적 예시·선택형 로그인 UI와 해당 코드만 비인증 요청에 제공한다. 공개 로그인 UI를 일반 사용자용 모아 앱으로 확대하지 않았다. 모든 앱 파일을 Worker에 내장하고 정적 fallback은 앱 없는 안내 페이지만 둔다. 정확한 소유자 UUID를 사전 검사하고, 실제 JWT 서명/프로젝트/현재 Auth 세션은 기존 `moa_account_status` RPC가 검증한다. 실패·만료·위조·다른 사용자·RPC 장애는 차단한다. 쿠키는 Secure/HttpOnly/SameSite=Strict, Origin 검사와 요청 크기 제한을 적용했다.
