# 글로벌 현지화 코드치환 재발방지

## 발생 사례 — DEVICE CHECKUP 2026-09-03

글로벌 현지화 생성기가 HTML 전체에 단순 문자열 치환을 적용하면서, 사용자에게 보이는 문구뿐 아니라 인라인 JavaScript와 DOM 구조 식별자까지 번역한 회귀가 발생했다.

실제 확인된 변형 예:
- `fitKeyboard` 같은 함수명
- `startKeyboard / exitKeyboard / resetKeyboard` 같은 DOM id
- `ShiftLeft / ShiftRight / MetaLeft / MetaRight / ArrowLeft / ArrowRight`처럼 브라우저 표준 이벤트 코드에 포함된 `Left / Right`

베트남어에서는 `fitKeyboard`가 공백이 포함된 현지어 식별자로 바뀌어 JavaScript 문법 오류가 발생했다. 일부 다른 언어는 번역 결과가 우연히 유효한 식별자여서 빌드가 성공해도 동작 의미가 바뀔 수 있었다.

핵심 실패 원인:

> **표시용 자연어와 프로그램 구조 토큰을 같은 전역 문자열 치환 대상으로 취급했다.**

코드 생성 성공·배포 성공만으로는 이 유형을 잡지 못했다.

## 재발 방지 원칙

페이지형 제품의 글로벌 현지화에서 다음을 공통 적용한다.

1. **UI 자연어와 프로그램 구조를 분리한다.**
   - 함수명
   - 변수명
   - DOM id/class의 구조용 식별자
   - 브라우저/OS 표준 코드 문자열
   - API 이름
   - storage key
   - 이벤트명
   은 번역 대상이 아니다.

2. HTML 전체에 무차별 `str.replace()` 방식으로 현지화를 적용하지 않는다.
   - 번역 가능한 텍스트 노드/속성/메시지 리소스만 대상으로 한다.
   - 구조와 로직이 포함된 `<script>`는 별도 자원으로 취급한다.

3. 공통 기능 로직은 언어별 복제·번역보다 **canonical 코드 한 벌**을 재사용한다.
   - 언어별로 바뀌어야 하는 것은 메시지/라벨 리소스로 분리한다.

4. 배포 전 artifact 수준 검증을 강제한다.
   최소 검사:
   - 모든 생성 HTML 수
   - sitemap URL 수
   - 내부 href/src 존재
   - duplicate id
   - canonical/hreflang
   - 비한국어 원문 누출
   - 모든 외부 JS syntax
   - 모든 inline JS syntax
   - 제품별 구조 invariant

5. **문법 PASS만으로 충분하지 않다.**
   표준 코드 토큰이 현지어로 변형돼도 문법상 유효할 수 있으므로, 제품별 중요한 invariant를 확인한다.

6. 검증 실패 시 배포를 차단한다.
   - Build 성공
   - Artifact QA 성공
   - Deploy 성공
   을 서로 분리한다.

## 공통 적용

이 규칙은 DEVICE CHECKUP 전용이 아니다.

랜덤뽑기, 성경 읽기 웹서비스 및 이후 모든 페이지형 글로벌 현지화에서 **자연어 번역이 코드 구조를 변경하지 않는지**를 반드시 확인한다.
